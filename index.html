User roles

Three experiences, one shared trip system.

Passenger

Request, track, pay, and rate.

  • Register and login
  • Choose pickup and destination
  • View driver details and live arrival
  • Pay by cash first and review ride history
Driver

Go online, accept rides, and earn.

  • Register and upload documents
  • Go online or offline
  • Accept or reject ride requests
  • Navigate, complete trips, and view earnings
Admin

Control safety, fares, and operations.

  • Approve drivers and suspend accounts
  • View trips, payments, and reports
  • Manage fare rules and platform settings
  • Monitor earnings and marketplace health

Ride flow

The MVP follows one clear trip lifecycle.

Each trip should move through explicit statuses so mobile apps, admin dashboards, notifications, and payments always agree on the same ride state.

  1. RequestPassenger selects pickup, destination, and requests a ride.
  2. MatchNearby eligible online drivers receive the request.
  3. AcceptThe first driver acceptance locks the trip and notifies the passenger.
  4. PickupDriver location updates power the driver-coming screen.
  5. TripDriver starts and completes the trip with auditable timestamps.
  6. CloseoutPassenger pays cash, then both sides can rate and review history.

System architecture

Separate the marketplace into focused services and clients.

The recommended first build is a Flutter app pair, a Node.js API, PostgreSQL, realtime location channels, Firebase Cloud Messaging, and a web admin dashboard.

Mobile

Flutter Passenger & Driver Apps

Shared design system with role-specific screens for booking, accepting, tracking, trip actions, profile, history, and earnings.

API

Node.js Backend

Owns users, drivers, vehicles, trips, fare rules, payments, ratings, notification triggers, and admin permissions.

Data

PostgreSQL

Stores normalized records for users, drivers, vehicles, trips, payments, ratings, notifications, documents, and audit logs.

Realtime

WebSockets or Managed Realtime

Streams driver availability, ride offers, ride status changes, and live coordinates during pickup and active trips.

Maps

Google Maps or Mapbox

Provides geocoding, map display, distance estimates, route previews, and driver navigation handoff.

Ops

Admin Dashboard

Hosted on Vercel with views for approvals, passengers, trips, payments, reports, fare settings, and support actions.
